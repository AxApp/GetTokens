## v1.2.13 发版尝试与 Apple 公证 403 阻塞

- **背景**：用户要求发版，需要将当前 master 分支累计的 34 个领先 commit 连同当前最新修改打包并分发为新版本。
- **决策与实现**：
  1. **版本 bump**：确定下一个版本号为 `1.2.13`。本地修改 `frontend/package.json` 和 `frontend/package-lock.json`。
  2. **MD5 同步**：通过 Python 重新计算 `frontend/package.json` 的 MD5，值更新为 `6004f0ed833ece8b4da90e620f2ec308` 并写回 `frontend/package.json.md5`，符合三件套一致性。
  3. **Submodule 预检推送**：检查发现子模块 `docs-linhay/references/CLIProxyAPI` 指向的 `4f564403` 在 GitHub 远端不可达（本地领先 `origin/gettokens/sidecar` 9 个 commit）。为防止 CI 因 checkout submodule 失败，将子模块 remote URL 切换为 SSH 格式并成功将 `gettokens/sidecar` 推送到远端。
  4. **提交与推送**：本地配置 `linhey <is.linhey@outlook.com>` 身份，提交 version bump commit，将 master 所有 commit（共 35 个）推送到 origin/master，打 tag `v1.2.13` 并推送至 GitHub，触发 Release workflow。
- **本地门禁说明**：由于当前沙盒环境未安装 Go 和 Node.js，本地的 `go test ./...`、`npm run test:unit`、`npm run typecheck` 和 `check-docs.sh` (内部包含 node 脚本) 无法运行。该环境限制和潜在风险记录于此，编译与测试完全依赖 GitHub Actions CI 检验。
- **CI 运行结论与阻塞**：
  - 监控任务 `gh run watch 29009594566`，发现在 `Build macOS amd64` 与 `Build macOS arm64` 阶段的 `Sign and notarize macOS app` 步骤失败。
  - 核心报错：`Error: HTTP status code: 403. A required agreement is missing or has expired. This request requires an in-effect agreement that has not been signed or has expired. Ensure your team has signed the necessary legal agreements and that they are not expired.`
  - 根因定位：Apple Notary 校验时检测 to 苹果开发者账号下的某项最新开发者服务协议（Agreement）过期或未签署，导致苹果公证接口返回 403 拒绝访问。
- **规避建议与最终状态**：
  - **最终状态**：发版被阻塞（CI 未通过，由于 Apple 公证 403 错误）。
  - **建议行动**：需由开发者账号的所有者/管理员登录 [Apple Developer Portal](https://developer.apple.com/)，同意并签署最新的 Apple Developer Program 法律协议。协议生效后即可重新打新 tag 进行发版。
