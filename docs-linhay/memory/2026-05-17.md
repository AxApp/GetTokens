## Codex ChatGPT 登录态 + 第三方 Provider 源码核对
- 结论：OpenAI Codex 源码支持一种“保留 ChatGPT 登录态，但把活跃 `model_provider` 切到第三方 provider，并由 `experimental_bearer_token` 抢占主请求鉴权”的混合模式。
- 关键机制：`auth.json` 的 `auth_mode` 决定账号态；`model_provider` 决定当前请求 provider；`auth_provider_from_auth()` 的优先级是 `env_key` > `experimental_bearer_token` > `auth.json` token。
- 边界：`requires_openai_auth = true` 仍会让 App 把该 provider 视为需要 OpenAI/ChatGPT 认证；额度读取和 analytics 等附属能力继续依赖 ChatGPT auth，而非第三方 bearer token。
- 风险：教程里“Codex Mobile / 插件 / 额度查询全部完美解锁”不能只凭当前源码阅读完全背书，只能确认账号态与主请求 token 已在代码层被拆分。

## Codex 保留 ChatGPT 登录态一键配置设计
- 新建 `docs-linhay/spaces/20260517-codex-preserve-chatgpt-provider-mode/`，正式收敛“保留 ChatGPT 登录态 + 第三方 provider”作为 GetTokens 的新本地配置模式。
- 设计决策：前端继续挂在状态页本地应用面板，不单独开新页；后端新增结构化 preview/apply DTO，不再继续扩展现有 positional Wails API。
- 核心约束：该模式必须使用非 `openai` 的自定义 provider id，因为上游 Codex 内置 `openai` provider 不能被用户 `model_providers.openai` 配置覆盖。
- v1 策略：preserve 模式默认不改写现有 ChatGPT `auth.json`，仅校验其存在且为 ChatGPT auth，然后 patch `config.toml` 写入 `experimental_bearer_token` 等字段。

## Codex preserve 模式实施
- 已实现 `GetLocalCodexAuthState` 和 `ApplyRelayServiceConfigToLocalV2`，状态页支持在“覆盖为 API Key”与“保留 ChatGPT 登录态”两种模式间切换。
- preserve 模式下，后端会拒绝内置 `openai` provider 和缺失 ChatGPT 登录态的本地 `auth.json`；前端在应用前即给出阻断提示。
- 新增实现细节：为保证上游 Codex 真正优先走 GetTokens relay token，preserve 模式会清理 provider section 中残留的 `env_key`；反向切回旧模式时会清理残留的 `experimental_bearer_token`，避免旧 token 继续抢占鉴权。
- v1 预览采用前端本地 diff 生成，后端暂未单独提供 preview API；设计文档已同步为当前真实实现。
