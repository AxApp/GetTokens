## Account Runtime Authority V2 方向确定

- 用户明确授权 GetTokens 账号体系不保留历史运行兼容，可以采用破坏性架构。
- 两轮外部 wise-council 仲裁后确定：新建 `accounts-v2.sqlite`，一次迁移后只读 v2；不原地延续 v1，也不完全清空 API key/openai-compatible。
- `accounts-v2.sqlite` 只保存账号资产与 credential；`runtime-v1.sqlite` 保存带 TTL、可重建的 guard/quota/rate-limit/evidence；live session、WebSocket pin、refresh lease 只保存在内存。
- OAuth 迁移不复制旧 refresh token，只迁账号元数据并标记 `reauth_required`；API key 和 openai-compatible 可迁移。
- 账号所有权采用 `account_key + credential_generation + runtime_auth_id`；OAuth 同代 token 轮换使用 `token_revision` CAS。旧 generation 的 refresh 和运行事实无权影响当前 generation。
- R1 必须同时切换 v2 单一 credential source 并删除 GetTokens 的 auth-dir/FileTokenStore/watcher/config fallback runtime 入口；不允许双读、GET 隐式迁移或 feature flag 回退。
- route guard/runtime facts 从 channel routing `runtimeStates` 移出；provider identity 默认不得跨账号阻断。
- 完整实现方案：`docs-linhay/spaces/20260711-account-system-hardening/plans/account-runtime-authority-v2.md`。
