### Hunt: Codex WebSocket interrupted 日志佐证

用户反馈 Codex 会话 `019e90ad-2afe-7b50-9c27-35d44246338d` 使用 `GetTokens - http://cpa.host.dxy/v1`、模型 `gpt-5.5` 时大量出现 `Conversation interrupted`，而直配本地凭证不复现。正式 sidecar 日志 `/Users/linhey/.config/gettokens/sidecar.log` 佐证为 GetTokens Codex WebSocket relay 路径问题：`2026-06-04 11:02:22` 对 `gpt-5.5` 选择 `codex:apikey:3df2001c2d1b` 且 `websockets=true`，连到 `ws://cpa.host.dxy/v1/responses`；`11:22:50` 同 session `635931a8-9660-436b-8976-e97c90d95498` 上游 `session_closed`，随后 `pinned auth released`，原因是 `408 stream closed before response.completed`，之后同模型请求持续返回 `503 auth_unavailable: no auth available (providers=codex, model=gpt-5.5)`。

源码链路：Codex `responses_websocket.rs` 在 websocket `Ok(None)` 且未收到 `response.completed` 时返回 `stream closed before response.completed`；CLIProxyAPI `openai_responses_websocket.go` 在 data channel close 且未 completed 时写 408 error，并在 pinned auth 释放后进入后续 503；Codex TUI `input_restore.rs` / `turn_runtime.rs` 对 `TurnAborted` 渲染固定 `Conversation interrupted` 文案。当前结论：根因不在模型本身，直配本地凭证绕过 GetTokens WS relay / pinned auth / route guard，因此不复现。低风险规避方向是让本地 Codex relay provider 默认 `supports_websockets=false`，必要时用户手动启用 WS。

### Fix: Codex WebSocket interrupted 根治落地
