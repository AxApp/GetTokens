- 根因：sidecar 按 runtime auth/card 刷新，不按 OpenAI `account_id` 合并；同时 `app_session_terminated` 这类终态 OAuth 400 未归类为不可重试，导致每张卡最多 3 次 retry 并在失败后继续排入 auto-refresh。
- 修复：Codex OAuth refresh 将 `refresh_token_reused / app_session_terminated / invalid_grant / session has ended / please log in again` 归为不可重试；core auth manager 将这些错误标记为 reauth-required 并移出 auto-refresh schedule；凭证变化时重置 `LastError / Unavailable / NextRefreshAfter / ModelStates / quota` 等旧运行态。
- 验证：`go test ./internal/auth/codex`、`go test ./sdk/cliproxy/auth`、`go test ./sdk/cliproxy`。

## 请求账号候选池持久化打通
- 用户反馈“刷新出可用账号后，请求账号池仍依次尝试异常账号”；space：`docs-linhay/spaces/20260609-account-candidate-pool-state-persistence/`。
- 根因：账号池/Wails explain 把异常状态写入 `channel-routing/config.json.runtimeStates`，但 CLIProxyAPI 真实请求只读内存 `AccountRouteGuardStore`；sidecar channel routing 读取同一配置时也只解析 `channels`，导致账号池状态与请求候选池分裂。
- 修复：sidecar `account-route-guard` 合并消费持久化 `runtimeStates`；`MarkBlocked / ReplaceSource / ClearSource / ClearAuth` 将 route guard 状态回写到共享 runtime state；manual disabled 优先持久化真实 `acct_*` account key。
- 加固：sidecar 写 `runtimeStates` 时保留 `channels` raw JSON、`events` 和 `nextEventID`，避免丢失 Wails 侧 `manualRequestableAccountIDs / shadowEnabled / accountGroups.name` 等字段；清除单个 source 不误删同账号其他 source。
- 验证：`go test ./internal/gettokenshooks ./internal/cmd ./sdk/cliproxy ./sdk/cliproxy/auth -count=1` 通过；本轮未触碰正式版 App。
