## 账号删除局部刷新

- 背景：账号页删除单个账号后复用 `loadAccounts()` 的页面级 loading，导致列表整体切换为 skeleton，看起来像整页刷新。
- 决策：删除成功后先本地移除对应 `auth-file` / `api-key` 记录并清理选中态，再用 `loadAccounts({ showLoading: false })` 静默对齐 Wails 事实源。
- 验证：新增 `accountDelete.test.mjs` 覆盖局部移除与选中态清理；`npm run typecheck`、`npm run test:unit` 均通过。
- 文档：需求与验收记录在 `docs-linhay/spaces/20260507-account-delete-soft-refresh/README.md`。

## 请求编排 V1 apply / restore 闭环

- 决策：请求编排 V1 不新增 CLIProxyAPI 原生策略，但 `应用当前组` 不再只是前端标记；Wails 后端新增 config / runtime snapshot / apply / restore 接口。
- 实现：新增 `internal/wailsapp/request_orchestration.go` 和根层 `app_request_orchestration.go`；配置落盘到 `~/.config/gettokens-data/request-orchestration/config.json`，快照落盘到 `runtime-snapshot.json`。
- Apply：保存当前 relay routing 与账号 / OpenAI-Compatible provider 的 disabled 状态，然后按当前流程组 `enabledAccountIDs` 保留参与账号，禁用其他账号 / provider。
- Restore：按 runtime snapshot 恢复 relay routing YAML 和账号 / provider disabled 状态，并删除快照。
- 前端：`RequestOrchestrationFeature` 在 Wails live 数据源下先保存 flows，再调用真实 apply / restore；preview 或 sidecar 未 ready 时只做预览状态提示。
- 验证：`go test ./...`、`npm --prefix frontend run typecheck`、`npm --prefix frontend run test:unit` 通过；`npm --prefix frontend run build` 已输出 Vite 产物，本机 Node/Vite 进程 built 后未自动退出，已手动清理；`./scripts/wails-cli.sh build` 已完成 bindings 生成但同样卡在前端 build 阶段，已清理本次 wails/vite/esbuild 进程。
