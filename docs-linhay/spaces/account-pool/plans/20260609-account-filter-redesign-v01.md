# 20260609 Account Filter Redesign Plan

## 目标

把账号池筛选重构为更贴近业务诊断的结构：
- “其他”从预组合条件改成三个可独立组合的业务维度：额度、余额、今日使用
- “状态”为异常补充动态请求状态码筛选，如 `401 / 402 / 403 / 429`

## 约束

1. 不改动 sidecar 或后端接口，筛选口径继续基于现有 quota / billing / usage summary 数据。
2. 保留账号池现有三大分组：`套餐与来源`、`状态`、`其他`。
3. 继续兼容已有本地筛选存储，旧结构仅用于迁移读取。

## 实施步骤

1. 先更新前端单测，锁定新筛选状态与工具栏结构。
2. 重构 `AccountsFilterState.resource` 为独立维度。
3. 为 `AccountsFilterState.status` 增加请求状态码子维度，并从账号错误证据中提取可选 code。
4. 更新 `AccountsToolbar` 交互与筛选摘要文案。
5. 更新 stories / locale / 相关源码断言。
6. 跑账号池相关测试并产出浏览器截图。

## 验收

1. 用户能直接看到六个业务筛项：`有额度 / 无额度 / 有余额 / 无余额 / 今日有使用 / 今日无使用`。
2. 用户可组合不同维度，例如 `有额度 + 无余额`。
3. 用户能在异常账号中按请求状态码筛出 `401 / 402 / ...`。
4. 旧本地存储不会导致崩溃，且能迁移到新筛选模型。
5. `node --test` 的账号池筛选相关测试通过。
