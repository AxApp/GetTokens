## Codex auth-file WebSocket 语义修正
- 撤回上一条“auth-file 默认注入 `websockets=true`”实现方向：auth-file / OAuth Codex 不应在合成层或 filestore 层写入默认 `Attributes["websockets"]`，否则会绕过本地 Codex `supports_websockets` 与用户显式配置语义。
- 新决策：CLIProxyAPI 侧新增请求期 WebSocket capability policy。Codex auth-file 默认只表示“允许跟随下游 Codex WebSocket 请求走上游 WebSocket”；只有 auth-file 显式 `websockets=false` 才关闭。`codex-api-key` 仍只尊重配置里的显式 `websockets=true`，不默认开启。
- 已调整：`sdk/cliproxy/auth/websocket_policy.go` 集中承载策略；`CodexAutoExecutor` 与 Responses WebSocket handler 复用该策略；`internal/watcher/synthesizer` 与 `sdk/auth/filestore` 只保留原始 metadata，不注入默认 attribute。
- 验证：`go test ./sdk/cliproxy/auth ./internal/runtime/executor ./sdk/api/handlers/openai ./internal/watcher/synthesizer ./sdk/auth` 通过。
- 真实联调：把正式环境 Codex OAuth JSON 补齐到 dev `auth-dir` 后，使用当前重建的 dev sidecar 发起 `ws://127.0.0.1:18317/v1/responses` 下游 WebSocket 请求，模型 `gpt-5.3-codex` 返回 `response.completed`，日志出现 `codex websockets: upstream connected ... auth=auth-3.json url=wss://chatgpt.com/backend-api/codex/responses`，确认 auth-file 缺省可跟随下游 WebSocket 走上游 WebSocket。

- 兼容补齐：Codex 账号列表加载 usage 改为按实际展示的 `orderedRows` 映射账号记录，避免 `openai-compatible:*` provider 卡片只参与展示却没有 usage 查询。
- 验证：新增红灯测试覆盖 live 刷新调度条件；`npm --prefix frontend run test:unit -- src/features/accounts/tests/accountUsage.test.mjs src/features/codex/codexAccountList.test.mjs` 和 `npm --prefix frontend run typecheck` 通过。

## CLIProxyAPI 系统代理出口开关
- 用户要求：GetTokens 是本地应用，但 `cli-proxy-api` sidecar 出口流量没有被 Proxyman 接管；需要在设置页新增开关，让 sidecar 在无账号级/全局 `proxy-url` 时跟随系统代理。
- 决策：代理优先级为账号级 `proxy-url` > 全局 `proxy-url` > context roundtripper > `use-system-proxy` > 直连；显式 `direct` 继续强制绕过全部代理。
- 实现：CLIProxyAPI fork 新增 `use-system-proxy`，HTTP、management `api-call`、Codex WebSocket、Claude uTLS 专用链路都接入系统代理；macOS 通过 `scutil --proxy` 读取 HTTP/HTTPS 代理，并优先尊重环境变量。
- GetTokens 接入：设置页新增“网络代理 / 跟随系统代理”开关，读写 `~/.config/gettokens-dev/config.yaml` 或正式 profile 的 `config.yaml`，sidecar ready 时通过 `PUT /v0/management/config.yaml` 热应用。
- 验证：`go test ./internal/sidecar ./internal/wailsapp`、`npm --prefix frontend run typecheck`、`npm --prefix frontend run test:unit`、CLIProxyAPI 相关 Go 测试通过；已重建 `build/bin/cli-proxy-api`。Proxyman 系统代理为 `127.0.0.1:9090` 时，sidecar `api-call` 请求 `https://www.example.com/?gettokens_proxy_probe=20260518`，Proxyman HAR 中出现 `_clientName=cli-proxy-api`、`_clientBundlePath=.../build/bin/cli-proxy-api` 的 CONNECT 记录，确认出口被接管。
- 启动期补强：若用户在 sidecar 非 ready 阶段切换“跟随系统代理”，App 先写入本地 `config.yaml` 并标记 pending；sidecar ready 回调会自动 `PUT /v0/management/config.yaml` 应用最新配置，避免启动过程中切换只能等下次重启。验证：`go test ./internal/wailsapp -run 'Test.*SidecarProxySettings'` 与 `go test ./internal/sidecar ./internal/wailsapp` 通过。
- Proxyman A/B 实测：通过 `proxyman-cli clear-session/export-log` 验证运行中 sidecar 热应用 `use-system-proxy:false` 后请求 `www.example.com` 导出为空；热应用 `use-system-proxy:true` 后同域名 HAR 出现 1 条 `_clientName=cli-proxy-api`、`method=CONNECT`、`status=200` 记录。测试后已恢复 dev config 原值。
