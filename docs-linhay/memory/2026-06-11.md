## Codex model catalog display_name / alias 边界修正
- 用户追问账号详情 `CODEX 模型` 下拉中的 `GPT 5.4` 来源，并指出 relay/model catalog 正常不应生成 alias，随后继续追问 catalog `display_name` 为什么和原始值不一致。

- 根因：同一个 `Alias` 字段被混用为“可请求 route alias”和“人类展示名”。当 alias 带空格或只是大小写展示名时，slug 解析已回落到原始模型名，但 display_name 仍被 alias 覆盖，导致目录展示名与原始模型值不一致，并把 `GPT 5.4` 带入前端候选。
- 修复：静态目录和 Codex 本地 `models_cache.json` 的 `display_name` 不再生成 `OpenAICompatibleModel.Alias`；GetTokens catalog 的 `display_name` 只在 alias 是真正 route alias 时采用，否则回落到 slug/原始模型名；catalog trace 同步使用同一解析函数。
- 验证：先用目标测试确认旧实现红灯，再修复；`go test ./internal/wailsapp -run 'Test(BuildGetTokensCodexModelCatalog|ListRelaySupportedModels|ParseSidecarModelDefinitions|LoadLocalCodexModelsCacheReadsModelsCacheJSON|RelayModelCatalogTraceWrittenFromAccountSnapshots)'` 与 `go test ./internal/wailsapp` 通过。
