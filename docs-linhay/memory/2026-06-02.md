## Codex 删除账号后运行会话复活排查

- 根因定位在 CLIProxyAPI auth synthesis：SQLite 统一账号库存在后，`synthesizeFileAuths` 仍只在账号库内有 `auth-file` kind 时跳过旧 Codex JSON；账号被删除或账号库为空时，`auth-dir/*.json` 残留文件会在 sidecar 重启首次 synthesis 中被重新合成为运行账号。
- 修复边界：只要配置了 `account-store-db` / `accounts-v1.sqlite`，即使 DB 缺失、不可读或 active account 数量为 0，也视为 Codex runtime source of truth；禁用 Codex API key / OpenAI-compatible legacy config fallback，并跳过 legacy Codex auth JSON。
- 同步修复 synthesis-pass cache：单独缓存 `AccountStoreActive`，避免空账号库第一次判断为 active、后续因 `len(accounts)==0` 又退回 inactive，导致多个遗留 JSON 文件中的后续文件复活。
- 已通过 `go test ./internal/watcher/synthesizer` 和 `go test ./internal/watcher/... ./sdk/cliproxy/...`。
- 用户确认迁移完成后 SQLite 是唯一账号源；legacy `auth-dir/*.json`、`codex-api-key`、`openai-compatibility` 只作为 account-migration API 的迁移输入保留，不再作为运行态 fallback。
