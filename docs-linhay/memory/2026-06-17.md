## 账号卡片 quota-empty 误报排查

- 用户反馈 PLUS 账号明明有额度但卡片显示“额度已空”。只读检查正式 sidecar `/v0/management/gettokens/quota-status` 后确认：PLUS auth-file `acct_751d74a2...` 的 quota fact 为 available，5H 99%、7D 75%，但账号处于 `manual-disabled`；PRO API key `acct_dd2172ea...` 5H 94%、7D 52%，仍在实际请求中被选中且 `/v1/responses` 返回 200。
- 根因定位到前端 `AccountCard` / `buildQuotaBlockBadgeLabel`：旧逻辑把任意 quota runtime `blocked=true` 都 fallback 成“额度已空”，没有区分 `manual-disabled`、`rate-limit` 与真正的 `quota-empty`。
- 修复：新增 `hasQuotaEmptyBlock()`，只有 `sources[].source == quota-empty` 或 `blockReason` 明确包含 quota empty/exhausted 时才渲染空额度 badge，并同步卡片 critical tone 判定；手动禁用只显示禁用状态，不再覆盖新鲜正额度窗口。
- 验证：`node --test-name-pattern 'quota display preserves sidecar route guard explain fields|quota blocked badge' frontend/src/features/accounts/tests/accountSelectors.test.mjs` 与 `npm --prefix frontend run typecheck` 通过。完整 `accountSelectors.test.mjs` 仍有一条既有 loading/fact 断言失败，非本轮引入。
- 沉淀：已更新 `.agents/skills/gettokens-domain-engineering/SKILL.md`，记录“通用 blocked 不等于 quota-empty”的账号池领域规则；不升级 `AGENTS.md`。
