### Bug Fix: curl_variables_json 列缺少迁移导致已存在 SQLite 数据库 500

**问题**：写入 credential 时 sidecar 返回 500 错误：
`SQL logic error: no such column: curl variables_json (1)`

**根因**：`curl_variables_json` 列虽然在 `CREATE TABLE` 和 `SELECT/INSERT` 中已定义，但 `EnsureSchema` 函数缺少对应的 `ensureTextColumn` 迁移调用。新建数据库不受影响，但已有数据库缺少该列导致查询失败。

**修复**（sidecar repo `docs-linhay/references/CLIProxyAPI`）：
- `internal/gettokens/accountstore/store.go`: 在 `EnsureSchema` 中添加 `curl_variables_json` 列的 `ensureTextColumn` 调用
- `internal/gettokens/accountstore/store_test.go`: 添加 `TestStoreEnsureSchemaAddsCodexAPIKeyCurlVariablesJSONColumn` 测试，验证 DROP COLUMN 后 EnsureSchema 能恢复列

**验证**：
- 迁移测试通过：模拟已有数据库缺少列，确认 EnsureSchema 自动添加
- Go 全量测试通过（accountstore 模块）
- Sidecar 二进制已重新构建（commit: df370a6f，在 `gettokens/sidecar` 分支）

**教训 & AGENTS.md 更新**：

### Decision: DeepSeek 余额展示改走 codex-api-key 新建路径

**背景**：DeepSeek 卡片不再显示余额，根因是 Unified Compose 选择 DeepSeek preset 后创建为 `openai-compatible`，而该账号模型不承载 `quotaCurl` / `billingCurl` / `quotaKey`，导致余额刷新链路不会触发。

**决策**：不处理历史兼容和迁移；后续带 `quotaCurlTemplate` 或 `billingCurlTemplate` 的 preset（如 DeepSeek）在 Unified Compose 中直接创建为 `codex-api-key`，复用现有 quota/billing 刷新与卡片展示链路。普通无余额模板 provider 仍创建为 `openai-compatible`。

**实现**：新增 `unifiedComposeCreateTarget` 模型 helper；`AccountsFeature` 提交时按 preset 是否具备 quota/billing 模板分流到 `CreateCodexAPIKey` 或 `CreateOpenAICompatibleProvider`；新增单测覆盖 DeepSeek payload 与结构断言。

**验证**：
- `node --test frontend/src/features/accounts/tests/accountDetailLayout.test.mjs frontend/src/features/accounts/tests/unifiedComposeCreateTarget.test.mjs`
- `cd frontend && npm run test:unit`
- `cd frontend && npm run typecheck`
- `go test ./internal/wailsapp ./internal/accounts ./internal/cliproxyapi`

**沉淀**：将“带 quota/billing preset 的供应商新建为 `codex-api-key`，复用现有余额刷新链路”的边界写入 `.agents/skills/gettokens-domain-engineering/SKILL.md`；该规则属于账号/quota 领域实现约束，暂不升级到 `AGENTS.md`。
