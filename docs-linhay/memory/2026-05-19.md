## Codex WebSocket 路由策略

- 用户指出下游已经发起 WebSocket 时，GetTokens/CLIProxyAPI 不应因为 `codex-api-key` 没有显式 `websockets=true` 就跳过高优先级代理账号；正确语义应是按下游协议尝试当前候选账号，只有显式 `websockets=false` 才禁用。
- 排查确认当前真实请求链路为 `Codex CLI -> 127.0.0.1:8317 -> auth-2.json OAuth -> wss://chatgpt.com/backend-api/codex/responses`，原因是 `AuthDataAllowsWebsockets` 只让 Codex auth-file 默认支持 WebSocket，而 `codex-api-key` 默认被判为不支持，导致 `preferCodexWebsocketAuths` 在下游 WebSocket 场景过滤掉最高优先级 `cpa.host.dxy` 代理账号。
- 已在 `docs-linhay/references/CLIProxyAPI` 修正策略：Codex provider 下账号默认跟随下游 WebSocket，显式 `websockets=false` 才禁用；更新选择器与 scheduler 测试，确认 `codex-api-key` 默认可参与 WebSocket 且保留优先级顺序。
- 验证通过：`go test ./sdk/cliproxy/auth`、`go test ./sdk/api/handlers/openai ./internal/runtime/executor`。注意当前运行中的 `/Applications/GetTokens.app` sidecar 仍是旧二进制，需重新构建/替换后实机路由才会生效。
