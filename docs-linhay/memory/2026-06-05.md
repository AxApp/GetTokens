## Wails / Relay 局域网支持

- Space：`docs-linhay/spaces/20260605-wails-lan-access/`。
- 决策：支持局域网访问限定在 Wails/Vite dev 预览和 sidecar relay 业务入口；不把 Wails 桌面应用改造成公网 Web 服务，不开放远程 management API。
- 实现：`frontend/package.json` 的 dev script 改为 `vite --host 0.0.0.0`；状态页新增 endpoint 选择模型，LAN 开启且存在 `kind=lan` 时优先选择 LAN 地址。
- 补充：运行状态页头部新增“打开 Web”按钮；Wails runtime 使用 `BrowserOpenURL` 打开当前 sidecar 端口的真实管理面板 `http://127.0.0.1:<sidecar-port>/management.html`，浏览器预览 fallback 到 `window.open`。明确不打开 `5173/#frame=status`，因为 Vite 浏览器页无 Wails bindings 时会走预览/模拟数据，不符合正式环境真实数据要求。
- 安全边界：sidecar `writeConfig` 继续保留 `host: ""` 业务监听，并强制 `remote-management.allow-remote=false`。
- 验证：`go test . -run 'TestWailsDevFrontendBindsToLAN|TestWailsConfigRegistersProdAndDevDeepLinkSchemes' -count=1`、`go test ./internal/sidecar -run 'TestWriteConfigCreatesMinimalConfig|TestWriteConfigPreservesCodexAPIKeys' -count=1`、`go test ./internal/wailsapp -run 'TestNormalizeRelayAPIKeys|TestBuildRelayServiceEndpoints' -count=1`、`node --test frontend/src/features/status/tests/relayLocalState.test.mjs frontend/src/features/status/tests/statusTypography.test.mjs`、`docs-linhay/scripts/check-docs.sh` 均通过；`npm --prefix frontend run typecheck` 被无关账号详情脏改动 `AccountsFeature.tsx` 缺少 `findOpenAICompatibleAccountForProvider` 阻塞。
- 沉淀判断：本轮不新增项目级 skill 或 AGENTS 规则；既有 `gettokens-domain-engineering` 的 relay/management 边界与 `gettokens-ops-governance` 的 Wails dev loop 已覆盖该模式。
