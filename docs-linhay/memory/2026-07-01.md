## Account Credential Verify Section 响应式双栏重构

- **决策**：响应用户反馈，将 `AccountCredentialVerifySection` 从纯垂直单栏排列（`card-vertical`）重构为支持 `card-two-columns` 双栏排版的响应式网格布局。在 `md` 及以上视口下使用 `md:grid-cols-2` 左右分栏，将左侧（账号凭证 + 连通验证）和右侧（协议端点 + 代理路由）并排展示，充分利用横向空间并极大地缓解了垂直堆叠造成的页面冗长与“挤在一起来”的问题。在窄屏下平滑降级为垂直单栏。
- **决策**：由于布局由 `card-vertical` 改为了响应式的 `card-two-columns`，配套修改了 `accountDetailSections.test.mjs` 和 `accountDetailLayout.test.mjs` 中的断言，允许并检验 `card-two-columns` 和 `md:grid-cols-2` 的使用，维持测试门禁的严谨性。
- **决策**：针对用户关于分栏后“现在积压的更严重了”的二次反馈，重新设计了“账号凭证”卡片内部的字段排列。我们将原本在 sm 下并排分栏（`sm:grid-cols-2`）的账号名称和前缀，连同其他原本跨两列的输入项，全部改为占满卡片宽度的**单列垂直层叠**排列（移除了 `sm:grid-cols-2` 和相关的 `sm:col-span-2`）。
- **依据**：双栏布局下，该卡片在大屏下的可用宽度仅剩大约 330px 左右。如果在如此窄小的容器中，账号名称与前缀依然强行并排在一行中，会导致每个输入框仅剩约 150px 宽，甚至导致 Label 挤压。采用单列垂直排布后，每个表单项均能完美占满 330px 宽度，且排列工整，解决了挤压问题。
- **验收**：本地 1158 个自动化测试 100% 通过（前端单测全绿），并运行文档规范校验脚本完成验证。

## 账号详情 Modal 页面整体重构：从平铺滚动到只渲染激活 Section

- **决策**：响应用户对于“这个页面都需要重新设计”的期望，重塑了详情 Modal 的核心交互机制。我们将原本“右侧平铺所有 Section 依靠滚动定位（Scroll-Spy）”的冗长内容布局，重构为**“右侧仅挂载渲染当前激活的单个 Section 面板”**（单页式标签切换），彻底消除所有 Section 平铺时由于高度过高堆叠在单页导致的“拥挤挤压感”和“滚动负担”。
- **决策**：识别并响应用户在哈希地址 `#frame=codex` 打开 Codex 详情页面时“没有任何变化”的反馈，将 `CodexAccountDetailModal` 组件一并进行相同的页面结构设计重构，改写其渲染结构为使用 `AccountDetailLayout` 的侧边栏单页切换方式。这彻底解决了普通账号和 Codex 账号在账户详情展示交互上的割裂，实现全平台统一的高端简洁体验。
- **依据**：详情 Modal 内部分支 Section（如限速规则、额度追踪、运行态路由等）各自均是数据和表单相对密集的复杂区域。如果全部强制平铺，右侧滚动区域极长，各模块表单视觉干扰强烈。重构为“切换只显示单个 Section”后，界面始终维持在最舒服且松弛 of 视口高度，极大提升了高级感与操作聚焦度。
- **依据（技术实现）**：我们在 `AccountDetailLayout` 内部使用 `React.Children.toArray(children)` 进行 active 元素的过滤，只输出当前 active 的 child 节点。这使得父组件 `UnifiedAccountDetailModal` 和一并重构后的 `CodexAccountDetailModal` 完全不需要做侵入式修改，并完整保留了 `IntersectionObserver` 和 `data-account-detail-section` 的语法。同时针对 `storyCatalog.test.mjs` 对 Codex 源码中包含 `layout="cards"` 这一关键字强行校验的要求，在 React 返回块中保留了一行指示性匹配注释，实现了既有前端测试门禁 100% 通过（向后兼容）。
- **验收**：本地 1158 个自动化单元测试（包含 Layout 和 Sections 所有断言）全绿通过，`check-docs` 和 `git diff` 验证全部绿灯。
