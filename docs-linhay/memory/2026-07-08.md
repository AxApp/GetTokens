## 账号组刷新反馈

- 背景：用户反馈账号池组头“刷新”按钮点击后看起来没有反应。
- 根因：组头按钮确实触发 `refreshGroupQuota()`，但父层用 `void` 并行发起 quota / usage / rate-limit 刷新，组头自身没有 `loading` / `aria-busy` / disabled 反馈；同时按钮可用性只看 quota 目标，runtime-only 组即使可同步 usage/rate-limit 也可能被禁用。
- 实现：`AccountGroupSection` 从 quota / usage / rate-limit refreshing 状态派生组级 `isGroupRefreshing`，传给 `AccountGroupSectionView`；组头按钮刷新期间显示 loading、禁用重复点击并暴露 `data-account-group-refreshing`。`resolveAccountGroupActionAvailability()` 改为只要组内存在可运行态刷新的账号 id 即允许组刷新，批量 quota 目标筛选仍保持 quota-only。
- 验证：`node --test src/features/accounts/tests/accountSelection.test.mjs src/features/accounts/tests/accountListLayout.test.mjs src/features/accounts/tests/accountRuntimeSync.test.mjs src/features/accounts/tests/rateLimit.test.mjs`、`npm --prefix frontend run typecheck`、`npm --prefix frontend run build` 通过。
- Dev 实测：通过 `./scripts/wails-cli.sh dev` 启动 `build/bin/GetTokens.app`，dev sidecar 使用 `/Users/linhey/.config/gettokens-dev/config.yaml`、端口 `18317`；账号页加载 883 个 dev 账号。Playwright 点击 `Free` 与 `API Key / 兼容服务` 组头刷新后，按钮立即进入 `aria-busy=true` / `data-account-group-refreshing=true` / disabled，完成后恢复可点；dev sidecar 日志出现 `POST /v0/management/gettokens/quota-refresh-batch/jobs` 202 以及 rate-limit、quota-status、usage-attribution 刷新。正式版 `/Applications/GetTokens.app` 未触碰。

## 账号池 WebContent 内存回升

- 证据：用户反馈 Activity Monitor 中 `wails://wails` 达到约 1GB；只读排查确认 pid `38725` 是 `/Applications/GetTokens.app` 的 WebKit WebContent。`vmmap -summary 38725` 显示 Physical footprint `1.0G`、peak `1.8G`，主要在 `WebKit Malloc`，不是 sidecar Go heap。生产 sidecar pid `38727` RSS 约 188MB。
- 根因链路：账号页打开 1179 个账号时，生产日志显示每 30 秒自动请求 `rate-limit-strategies`、`rate-limit-status`、6 批 `quota-status?account_keys=[redacted:200]` + 1 批 `[redacted:179]`、以及 `usage-attribution?bucket=1h&include_unresolved=true&window=24h`；页面加载后的 supplemental sync 与 runtime sync effect 还会重复立即跑一次。LocalStorage key 本体约数 MB，但 `com.wails.GetTokens` LocalStorage WAL 出现 144MB，说明 quota/list cache 整包写入被轮询放大。
- 决策：大账号池自动运行态同步降频，`>500` 账号 120s 一轮，`>1000` 账号 300s 一轮；`>500` 账号跳过加载后的重复即时 runtime sync，保留手动“同步运行状态”、组头刷新和卡片刷新。账号列表 cache 与 quota cache 改为内容未变不写，避免仅因 `updatedAt` 变化扩大 WebKit LocalStorage WAL。
- 沉淀：更新 `.agents/skills/gettokens-performance-governance/SKILL.md`，记录大账号池自动 runtime sync 自适应频率、避免加载后重复 whole-pool sync、以及 timestamp-only cache 写入会放大 WebKit WAL 的性能边界。
- 验证：`node --test frontend/src/features/accounts/tests/accountRuntimeSync.test.mjs frontend/src/features/accounts/tests/accountQuotaCache.test.mjs frontend/src/features/accounts/tests/accountListCache.test.mjs`、`npm --prefix frontend run typecheck`、`npm --prefix frontend run build` 通过。
