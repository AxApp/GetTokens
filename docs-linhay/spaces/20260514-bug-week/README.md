# Bug Week 零散问题处理

## 背景

当前进入 bug 周，需要一个统一空间承接杂项问题、回归修复、小范围体验缺陷和临时排障记录，避免零散问题分散在多个 feature space 中。

## 目标

1. 集中记录 bug 周内发现、确认、修复和验证的杂项问题。
2. 为每个问题保留最小可追踪上下文：现象、影响范围、复现方式、验收标准、验证结果。
3. 对超出“小修”边界的问题及时拆出独立 `space`，避免本空间演变成长期大需求池。

## 范围

- 零散 UI/交互缺陷、状态展示异常、文案/配置错误。
- 可在短周期内定位和修复的回归问题。
- 不需要独立需求设计的小型工程治理或测试补漏。
- bug 周内的排障记录、截图、验证结果与临时计划。

## 非目标

- 新功能开发。
- 需要产品设计、接口改造或跨模块重构的大需求。
- 长期 roadmap、版本发布计划或独立专题方案。
- 无法在本周内闭环且影响范围较大的问题；这类问题应拆出独立 `space`。

## 验收标准

1. 每个进入本空间的问题都有清晰复现条件或可观察症状。
2. 每个修复先补充或更新对应测试；若无法自动化验证，记录原因和手工验收步骤。
3. 涉及前端或桌面体验的问题，按需保留 before/after 截图到本空间 `screenshots/`。
4. 修复完成后记录验证命令、结果、残留风险和后续行动项。
5. 问题复杂度超过本空间边界时，创建独立 `space` 并在这里留下跳转链接。

## 问题分流规则

| 类型 | 处理方式 |
|------|----------|
| 小型 bug / 回归 | 留在本空间跟踪并修复 |
| 需要设计或多方案对比 | 拆独立 `space` |
| 影响接口、领域模型或状态流转 | 先补边界说明和测试计划，再决定是否拆独立 `space` |
| 只影响文档或治理规则 | 直接在本空间记录变更与验证方式 |

## BDD 场景

### 场景：收敛零散 bug

- Given bug 周内出现一个不属于既有 feature space 的问题
- When 问题被确认需要处理
- Then 在本空间记录问题现象、影响范围、复现步骤和验收标准

### 场景：问题超出杂项范围

- Given 一个问题需要跨模块改造、独立设计或多日交付
- When 评估后确认无法作为小修闭环
- Then 为该问题创建独立 `space`，并从本空间链接过去
