# 2026-05-31

## Codex DeepSeek routing reference

- 调研 `farion1231/cc-switch` 对 Codex + DeepSeek 的实现，参考源码按需拉取到 `docs-linhay/references/cc-switch/`，该目录由 `.gitignore` 忽略，不进入 git。
- cc-switch 的关键闭环：Codex 下游继续使用 Responses API，本地路由识别 provider `apiFormat=openai_chat` 后，把 `/responses` / `/v1/responses` / compact 转为 `/chat/completions`，再把 Chat JSON/SSE 转回 Responses；DeepSeek preset 包含 `deepseek-v4-flash`、`deepseek-v4-pro`、1000000 context 和 DeepSeek reasoning 映射。
- CLIProxyAPI 当前已有 `codex-api-key` Responses 执行器、`openai-compatibility` Chat Completions 执行器，以及 `OpenaiResponse -> OpenAI` translator；Responses <-> Chat/SSE 底层桥接不是从零实现，缺口主要是把 Codex route result 接到 openai-compatible executor 热路径，并补 DeepSeek reasoning 特化。
- 后续若实现 Codex 对 DeepSeek 支持，应在 GetTokens sidecar/channel routing 边界内新增 upstream protocol 标记和执行器接线，继续通过 `/v1/models?client_version` 暴露模型目录，不照搬 cc-switch 写 `~/.codex/model_catalog_json` 或单 provider 接管本地 Codex config 的模型。
- Codex route 下发给前端的模型候选也必须包含 DeepSeek/openai-compatible 的 Codex-facing alias；否则用户无法在 Codex 账号列表、模型映射、路由探测或本地应用流程里选择这些模型，按模型分流也无法被触发。
