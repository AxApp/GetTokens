## Route Guard v2：手动禁用与自动限流统一
- 根因：账号禁用后仍可能继续向旧上游发送请求，是因为已有 Codex WebSocket session 会复用 `pinnedAuthID` 和 upstream connection；disabled 只影响后续候选过滤，不能自动打断已建立连接。
- 决策：手动禁用和自动限流都归为“账号不应继续参与路由”的 Route Guard source。`manual-disabled` 由用户操作驱动，`rate-limit` 由限流评估驱动，两个 source 共用 deny 机制但独立清理。
- 实现：CLIProxyAPI fork 新增 `AccountRouteGuardStore` / `accountRouteGuardPolicy`；`RateLimitEvaluator` 每轮评估后刷新 `rate-limit` source；`Service.applyCoreAuthAddOrUpdate` 在 auth disabled 时写 `manual-disabled`，重新启用时清理该 source。
- WebSocket 行为：Codex auth 从可路由状态切到 disabled 时，立即调用 `CloseCodexWebsocketSessionsForAuthID(authID, "auth_disabled")` 关闭受影响上游 session，让客户端重连后重新选账号。本轮 P0 不做同 downstream WebSocket 内无感热迁移。
- 验证：sidecar fork `go test ./internal/gettokenshooks ./internal/runtime/executor ./sdk/cliproxy ./sdk/api/handlers/openai` 与 `go test ./...` 均通过。

## Route Guard P2：同 downstream WebSocket 内账号热切
- 决策：P2 切换边界固定为下一条 downstream request，不在同一条正在 streaming 的 response 中途迁移账号。
- 实现：`ResponsesWebsocket` 每轮 normalize 前检查当前 `pinnedAuthID` 是否被 `AccountRouteGuardBlocksAuth` 阻断；命中后释放 pin、关闭旧 execution session upstream 资源、启用完整 transcript replay，并保留 downstream WebSocket。
- 实现：`CodexWebsocketsExecutor.ensureUpstreamConn` 在同 execution session 中发现新 `authID` / `wsURL` 与旧 upstream 不一致时，以 `auth_rotated` 关闭旧 conn 并重新握手，避免新账号请求继续写入旧连接。
- 验证：新增测试覆盖同 session auth 变化必须重新 upstream 握手，以及 pinned auth 被 Route Guard 阻断后同 downstream 连接内切到 auth-b 且不泄漏旧 `previous_response_id`；相关包测试和 sidecar `go test ./...` 均通过。

## Codex API Key 禁用未生效修复
- 根因：账号页禁用 Codex API Key 后流量仍进入该账号，是因为 CLIProxyAPI fork 的 `config.CodexKey` 没有 `disabled` 字段，management `PUT /v0/management/codex-api-key` 收到的 `disabled:true` 在 sidecar 配置层被丢弃；`ConfigSynthesizer.synthesizeCodexKeys` 随后始终生成 active runtime auth。Codex 请求顺序调整能“恢复正常”只是把该账号排到后面，绕过了 selector 命中。
- 修复：CLIProxyAPI fork 为 `CodexKey` 增加 `Disabled` 字段，`PatchCodexKey` 支持 `disabled`，synthesizer 在 disabled key 上生成 `Disabled=true` / `StatusDisabled` runtime auth，从而触发 `manual-disabled` route guard 和 Codex WebSocket guard 链路。
- 验证：已先补红灯测试 `TestConfigSynthesizer_CodexKeys_DisabledKeyStaysInRuntimeAsDisabled`，再修复并通过 `go test ./internal/watcher/synthesizer -run 'TestConfigSynthesizer_CodexKeys|TestConfigSynthesizer_CodexKeys_DisabledKeyStaysInRuntimeAsDisabled'`、`go test ./internal/api/handlers/management -run 'Test.*CodexKey|Test.*Codex'`、`go test ./sdk/cliproxy -run 'TestServiceApplyCoreAuthAddOrUpdate_DisablingCodexAuthGuardsRouteAndClosesWebsocket'`、`go test ./internal/wailsapp -run 'TestSetAccountDisabledSupportsCodexAPIKey|TestProbeCodexAccountRouting|TestDetectCodexRoutingProbeHit|TestSidecarRelayRequest'`。
- 产物：CLIProxyAPI fork 已提交并推送 `9164435d fix: preserve disabled codex api keys` 到 `origin/gettokens/sidecar`；主仓库 `docs-linhay/references/CLIProxyAPI` gitlink 已更新到该提交。已执行 `scripts/ensure-sidecar.sh darwin arm64` 重建本地 `build/bin/cli-proxy-api`，后续需重启 Wails / GetTokens 让运行中 sidecar 换到新二进制。
- 补充修复（同日）：`9164435d` 虽然加上了 `CodexKey.Disabled` 字段和 synthesizer 支持，但实际测试发现 `SaveConfigPreserveComments` 的 YAML 注释保留合并逻辑（`mergeMappingPreserve` + `reorderSequenceForMerge`）在序列元素合并时仍会丢失新增的布尔字段 `disabled: true`，导致磁盘 YAML 无该字段，file watcher reload 后 auth record 回到 Disabled=false，route guard 不会被触发。
- 实际定位方式：直接向运行中 sidecar 发 PUT（含 `disabled: true`），再 GET 验证内存配置有/无、磁盘 YAML 有/无，定位到问题只在持久化层。
- 补充修复：在 `SaveConfigPreserveComments` 的 `mergeMappingPreserve` 之后新增 `applyCodexKeyDisabledOverrides(original.Content[0], persistCfg)`，遍历 YAML 树中 `codex-api-key` 序列项按 `api-key` 匹配 in-memory config，强制同步 `disabled` 字段。
- 时效：整个禁用链路（Go App PUT → sidecar handler → YAML 持久化 → file watcher 150ms debounce → config reload → synthesize → MarkManualDisabledAuth → route guard deny）< 1 秒。
- 验证：`go test ./...` 全部通过（sidecar 40 包 + Go App 8 包）；手动 curl 测试 PUT disabled:true 后 GET 返回 `disabled: true` 且磁盘 YAML 包含 `disabled: true`。
- 文档：`docs-linhay/dev/20260522-codex-disabled-account-routing-fix.md` 记录了完整根因、架构、修复与时效。

## Sidecar YAML merge 调试经验
- `SaveConfigPreserveComments` 的处理链路：`yaml.Marshal(cfg)` → `yaml.Unmarshal` 为 node tree → `pruneMappingToGeneratedKeys`（限制 oauth 相关 key） → `mergeMappingPreserve`（递归合并保留注释） → `normalizeCollectionNodeStyles`（统一块样式）。合并中对序列元素的新增布尔字段可能被丢弃，需在合并后做字段级覆盖。
- 如果 handler 直接调 route guard（如 `MarkManualDisabledAuth`），会被 file watcher reload 从磁盘重读（不含 disabled）的流程覆盖掉。必须在持久化层修复。
- dispose pattern：对于 YAML comment-preserving merge 无法可靠保留的布尔字段，使用 post-merge override 模式（`applyCodexKeyDisabledOverrides`），从 in-memory config 强制接管输出。
