## Account quota refresh no-change diagnosis
- 现象：账号卡片点击额度刷新后数值没有变化。
- 运行态证据：`/Users/linhey/.config/gettokens/sidecar.log` 在 00:32 后反复记录 `GET /v0/management/accounts` 返回 500；直接请求 sidecar 复现错误 `ensure account store metadata: database is locked (SQLITE_BUSY)`。
- 锁持有证据：`lsof /Users/linhey/.config/gettokens/accounts-v1.sqlite` 显示 `TablePro` 与当前 `cli-proxy-api` 同时打开账号库。
- 关联改动：2026-05-31 的 sidecar-native quota refresh 改动后，Codex API key 额度刷新依赖 sidecar `quota-refresh` 与账号 SQLite；`internal/wailsapp/quota.go` 在刷新失败时会尝试返回已有 `quota-status` 缓存，因此 UI 可能表现为“刷新成功但额度不变”。
- 结论：当前首要根因是账号 SQLite 被锁导致 sidecar 账号读取失败；最近改动扩大了账号 store 与 sidecar runtime 的依赖面，并让失败更容易被旧缓存掩盖。
- 后续风险：需要考虑让账号 store schema/metadata 初始化避免每次读请求写库，或为刷新失败显式透出 degraded/error 状态，避免卡片静默显示旧额度。

## 账号详情 modal 满屏与独立路由
- 现象：账号详情 modal 不是满屏，且 Claude Code account-list 详情、account-list route probe 等 modal 缺少可直接恢复的独立 hash。
- 根因：`ModalFrame size="detail"` 仍使用 `max-w-[72rem]` 和视口边距；Claude Code account-list 详情只保存在本地 state；全局 hash canonicalizer 没有保留 `modal=<route>`。
- 决策：详情类 modal 使用满屏 detail shell；account-list 详情使用 `detail=<id>`，调试类 modal 使用 `modal=<route>`，关闭时只移除对应 marker。
- 落地：补齐 Claude detail route、Codex/Claude route-probe `modal=route-probe`，并让 global navigation 保留当前 frame/workspace 的 `detail` / `modal` 参数。
- 追加校正：账号详情满屏语义是遮罩覆盖整个应用窗口（含 sidebar），面板四周仍保留可见遮罩和投影间距；`ModalFrame size="detail"` 需要通过 `document.body` portal 挂载，避免被账号页内容容器或 sidebar offset 影响。
- 验证：前端 focused unit、typecheck、build 通过；无头浏览器确认 Accounts/Claude 详情与 Codex route-probe 可从 hash 直达并满屏。
- 沉淀：已更新 `AGENTS.md`、`.agents/skills/gettokens-domain-engineering/SKILL.md` 与 `docs-linhay/dev/20260522-unified-account-detail-system.md`。
