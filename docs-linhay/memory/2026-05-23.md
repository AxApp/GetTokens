## Codex thread goal read failure
- 结论：`TUI` 里的 `Failed to read thread goal` 是 `tui/src/app/thread_goal_actions.rs` 对 `app_server_session.thread_goal_get()` 失败的展示；真正的 RPC 路径在 `app-server/src/codex_message_processor/thread_goal_handlers.rs`。
- 失败条件：`thread/goal/get` 会在 goals feature 未开启、线程是 ephemeral、线程不存在、sqlite state db 不可用，或 `state_db.get_thread_goal()` 本身返回 SQLite/查询错误时失败。
- 风险：如果本地 state db 旧、迁移不完整或损坏，界面上就只会看到这类泛化报错，根因需要继续看 app-server 返回的 JSON-RPC error message。
- 这次实查结果：`~/.codex/state_5.sqlite` 的 `_sqlx_migrations` 已到 34，且日志里出现 `no such table: thread_goals`；这说明当前目标库路径上的状态库已经没有 `thread_goals` 表，TUI 报错不是空 goal，而是后端查询目标表失败。
- 关联文件：`~/.codex/state_5.sqlite`、`~/.codex/goals_1.sqlite`、`/Users/linhey/.codex/logs_2.sqlite`。其中 `goals_1.sqlite` 虽然有 `thread_goals` schema，但当前这条 `thread/goal/get` 路径实际命中的还是会报缺表的那套状态链。
