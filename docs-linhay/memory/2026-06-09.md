## 账号池规模优化 Phase 4
- sidecar 主动批量刷新新增 job API：`POST /gettokens/quota-refresh-batch/jobs` 立即返回 `job_id`，`GET /jobs/:job_id` 读取 `pending/running/succeeded/failed`、逐账号 `items/errors` 和时间戳；job 为进程内 runtime 状态，sidecar 重启后不恢复。

## 账号池刷新任务取消修复
- 用户反馈“全刷 1000+ 账号后删除账号，已删除账号仍请求；关闭 App 时 sidecar 因请求未结束无法退出”。
- sidecar quota batch refresh job 已新增 `canceled` 终态和 cancelable context；删除账号会取消命中 account keys 的 pending/running job，`Server.Stop` 会取消全部 pending/running job。
- worker 发起单账号 quota curl 前重新读取 account store 确认账号仍存在，避免 job 启动时的账号快照在删除后继续驱动请求。
- 前端轮询把 `canceled` 视为终态；领域规则已沉淀到 `.agents/skills/gettokens-domain-engineering/SKILL.md`。
- 追加验收发现：本仓 `build/bin/cli-proxy-api` 已是新 sidecar，但 `wails dev` 重新打包后的 `build/bin/GetTokens.app/Contents/MacOS/cli-proxy-api` 可能仍是旧副本；已改 `scripts/wails-cli.sh`，在 dev watcher 中持续同步安装 sidecar 到 dev bundle。
