# 2026-05-26 账号详情密度整理会话蒸馏

## 背景
这轮会话围绕 `accounts` 详情页持续做降噪和压缩，重点是 `auth-file` / `api-key` 两类详情的可读性与占地。

## 蒸馏出的模式
1. 先找重复信息，再找尺寸问题。
2. 详情页顶部只保留运行态信号，不重复展示 quota / balance / 原始 auth 内容。
3. 复用已有卡片组件比造一套 detail-only 版本更稳，尤其是 `QuotaBars`。
4. API Key 凭据区块适合上下堆叠，字段名嵌入输入框更省宽度。
5. 详情 hash 恢复必须保留，layout 变更不能把 deep link 弄丢。

## 适用边界
- 适用：账号详情、密度压缩、重复字段去重、卡片与详情样式统一。
- 不适用：纯数据模型变更、与布局无关的业务逻辑改动。

## 验收习惯
- 先写 focused test 锁结构，再改 UI。
- 改完后跑 `typecheck`、`build`，并做浏览器复验。
- 发现重复内容时，优先删重复区块，不要只缩字号或挤间距。
