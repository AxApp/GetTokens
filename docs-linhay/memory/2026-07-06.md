## 账号导入交互重构 (Account Import Redesign)

- **痛点修复**：重构了 `AccountImportPage.tsx` 和 `AccountImportModal.tsx`（以及队列展示组件 `AccountImportQueueList.tsx`）。解决了原页面在文件拖拽与手动粘贴上区域分裂、卡片套卡片、队列直接展示难读的 JSON raw 文本、无法在导入前就地修改账号字段、缺少多选勾选导入与批量清空等交互极差的问题。
- **重构实现**：
  1. **左侧输入面板统一**：使用 AntD `Tabs` 组件将“文件导入”和“文本粘贴”整合入单个输入面板；拖拽区域支持多文件拖放，文本粘贴区在输入合法时即时激活“添加”按钮。
  2. **右侧工作台管理 (Pre-Import Workbench)**：展示队列不再显示冗长 JSON，而是生成为结构化、卡片化的预览，包含了序号、多选框、数据源标签（文件/粘贴/剪贴板）、类型标签（AUTH FILE/API KEY/PROVIDER）、名称及核心连接信息。
  3. **就地修改验证 (Inline Form Edit)**：每个待导入卡片均提供“编辑”按钮，点击即可就地展开微型编辑表单修改字段。保存时重新触发本地格式校验，如数据恢复合法即刻自动消除 Error 错误状态。
  4. **智能剪贴板检测 (Smart Clipboard Detection)**：当用户打开页面/弹窗时，会自动读取检测剪贴板。如剪贴板含合法的账号 JSON，在顶部显示精致的 Alert Banner 提示“一键粘贴并解析”，极大提升高频导入效率。
  5. **批量多选勾选**：支持 checkbox “全选”/“全消”、批量删除、仅导入被勾选的账号候选。
- **技术升级**：在 `accountTransfer.ts` 中新增了 `validateAccountImportPayloadItem` 校验机制，并让上传/压缩包导入直接解析 JSON bytes 生成 API Key / Provider / Auth File 卡片；只有无法解析的 JSON 才回落为 raw upload-file。
- **校验回归**：
  1. 单元测试回归：在 `accountTransfer.test.mjs` 中新增了针对 `validateAccountImportPayloadItem` 在不同账号类型（API Key、Auth File、OpenAI-Compatible）下的合法/非法测试用例；更新 `accountCardInteractions.test.mjs` 中的 assertions 以匹配新的 Tabs/Checkbox 结构与移除 `font-medium` 类。全部 1111 个前端测试 100% 通过（`npm run test:unit`）。

- **问题**：浏览器标注指出点击账号卡刷新按钮时卡片缺少可见动画反馈；真实 usage/rate-limit/quota 刷新态可能很快结束，用户看不到卡片级响应。
- **修复**：`AccountCard` 点击刷新后为本卡片保留 900ms 本地 `refreshFeedback`，`AttributionCard` 将本地反馈与真实 quota/usage/rate-limit 刷新态合并传给 `AccountCardFrame`；外壳输出 `data-account-card-refreshing` 与 `aria-busy`，CSS 增加轻量 pulse/sweep 动画。
- **验证**：`node --test src/features/accounts/tests/rateLimit.test.mjs`、`npm run typecheck` 通过；浏览器刷新后点击卡片刷新按钮，80ms 内目标卡片出现 `data-account-card-refreshing="true"` 与 `aria-busy="true"`。

## 超多账号刷新 Batch 路径回归

- **根因**：此前为超多账号导入/刷新新增的 quota batch 路径只接入了选中批量刷新；账号池顶部全局刷新 `refreshAccountsRuntime` 与分组刷新 `refreshGroupQuota` 仍保留 `accounts.map(refreshCodexQuota)` / `groupAccounts.forEach(refreshCodexQuota)`，在 600+ 账号场景会重新退化为大量单账号并发刷新。
- **修复**：`AccountsFeature` 将全局刷新与分组刷新切换到 `refreshAccountQuotasBatch(...)`，usage 与 rate-limit 刷新保持原批量入口；单卡刷新仍保留单账号刷新语义。
- **验证**：新增 `accountRuntimeSync.test.mjs` 静态约束，锁定可见批量刷新入口必须调用 batch quota 刷新且不得再展开单账号 quota fan-out；`node --test src/features/accounts/tests/accountRuntimeSync.test.mjs`、`npm run typecheck` 通过。

## 账号导入弹窗 Tab 切换宽度跳变

- **根因**：`ModalFrame` 的宽度使用 `calc(100vw-1.5rem)` 这类无效 CSS，浏览器丢弃后 AntD modal 退回按内容 shrink-wrap；文件 Tab 的 Upload 内容较宽、粘贴 Tab 的 TextArea 内容较窄，所以切换时 modal 从 442px 缩到 298px。修正 `calc` 后又确认普通 modal 遮罩会避开 sidebar，宽度公式还必须减去 `--app-sidebar-width` 并与 `sm:px-6` 的 3rem 横向 padding 对齐。
- **修复**：`ModalFrame` 的 Tailwind 任意值改用 `_` 表达合法空格；AntD `width` 改为合法 `calc(...)`，普通 sidebar-inset modal 使用 `calc(100vw - var(--app-sidebar-width, 0px) - 3rem)`。
- **验证**：新增/更新 `accountDetailLayout.test.mjs` 对 ModalFrame 宽度公式的源码约束；`node --test src/features/accounts/tests/accountDetailLayout.test.mjs`、`npm run typecheck`、`npm run build` 通过。浏览器 730×863 复测：文件 Tab 与粘贴 Tab 的 modal 均为 442px，输入区与队列区均为 386px。
