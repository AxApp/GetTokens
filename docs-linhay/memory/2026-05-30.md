## 账号凭证 SQLite token refresh 写回

- 用户确认迁移后 `auth_file_accounts.auth_json` 必须承载完整 auth-file JSON，不能再依赖旧 `codex-*.json`。凭证 refresh 会更新，因此 sidecar 需要在 refresh 成功后把新 token payload 写回 SQLite。
- 根因：迁移后 runtime auth 从 SQLite 合成，但 Codex 自动 refresh 成功后走 `coreauth.Manager.Update()` 的通用持久化入口；该入口原本仍是文件 store 语义，导致迁移后的 auth-file 账号没有稳定写回 `auth_file_accounts.auth_json`。
- 修复边界：sidecar 新增 account-store token store 包装层。`Auth.AccountKey=acct_*` 且账号为 `auth-file` 时，`Manager.Update()` 持久化会更新原账号的 `auth_file_accounts.auth_json`，保留 `account_key`，不新建账号卡，不写旧 auth-file；account store 内的非 `auth-file` 账号也不会 fallback 到旧文件 store。
- 运行时 token refresh 是当前 runtime 生成的新 credential snapshot，只更新类型表和 `updated_at_unix_ms`，不递增 `account_cards.revision`，避免重新排队 runtime apply；management API 发起的凭证/配置编辑仍必须 bump revision 并触发 apply。
- 已补测试覆盖 `UpdateAuthFileCredential` 不改 revision、`coreauth.Manager.Update()` 真实入口更新 SQLite、非 account-store auth 才 fallback、account-store 非 auth-file 不 fallback、refresh payload 缺套餐时保留已有 `plan_type`。
