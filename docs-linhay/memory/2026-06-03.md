## Codex Live Sessions 账号身份归并修复

- Space：`docs-linhay/spaces/20260603-codex-live-session-account-identity/`。
- 根因：live-session tracker 记录的是请求发生时的 runtime `authID`，统一账号池当前身份是 `acct_* accountKey`；账号删除、禁用或迁移后，默认运行会话列表仍展示旧 runtime auth 行，容易被误读为这些账号仍可参与路由。
- 决策：账号身份过滤必须在 sidecar `GET /v0/management/gettokens/live-sessions` snapshot 出口完成；前端只消费 `accountKey/authDetached/authDisabled`，不得用本地缓存或字符串前缀猜测账号是否还存在。
- 实现：Codex HTTP / WebSocket live request start 记录 `accountKey`；默认 snapshot 过滤 detached/disabled runtime auth；`include_detached=true` 保留诊断全集并标记 `authDetached/authDisabled`；Wails DTO、前端 adapter/type 和诊断摘要同步 `account_key`。
- 验证：sidecar module 定向测试 `go test ./internal/gettokenshooks -run 'TestLiveSessionsRouteReturnsWebsocketRequestSnapshot|TestLiveSessionsRouteFiltersDetachedAndDisabledRuntimeAccounts|TestLiveSessionsObserveUsageRecordCreatesHTTPCompletedSession'`、`go test ./internal/runtime/executor -run 'TestCodex'` 通过；主仓 `node --test frontend/src/features/codex-live-sessions/model.test.mjs` 与 Wails DTO 定向测试通过；临时 sidecar 二进制在 `127.0.0.1:18317` live-session endpoint smoke 通过。
- 待验收：未直接替换用户当前 `/Applications/GetTokens.app` 运行中的 sidecar；真实桌面验收需在 App 重启或下一次 dev/build 启动后复核。
