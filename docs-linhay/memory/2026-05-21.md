## Codex OAuth 本地应用 tokens 结构修正

- 根因：GetTokens / sidecar 会把 Codex auth-file 归一化成扁平结构（`type=codex`、`access_token`、`id_token`、`refresh_token`、`account_id`），并移除 nested `tokens`；账号卡 OAuth 应用到 Codex 的后端写入逻辑只识别原生 Codex nested `tokens`，导致真实写入时报“Codex OAuth auth.json 缺少 tokens”。
- 修正：`buildRelayCodexOAuthAuthJSON` 现在同时接受原生 nested tokens 与 sidecar flat auth-file，写入 `CODEX_HOME/auth.json` 前统一转回 Codex 原生结构：`auth_mode=chatgpt`、`tokens.id_token/access_token/refresh_token/account_id`，并移除根部 API key / flat token 字段。
- 验证：新增 sidecar flat auth-file 回归测试；`go test ./internal/wailsapp` 通过。

## Codex API Key 本地应用 auth.json 最小化

- Codex 官方源码 `codex-rs/login/src/auth/manager.rs` 的 `login_with_api_key` 会写出只含 `auth_mode=ApiKey`、`OPENAI_API_KEY` 的 auth payload；`tokens`、`last_refresh`、`agent_identity` 不属于 API key 模式。
- GetTokens 账号模板应用到 Codex 的 API Key 模式已改为重建最小 `CODEX_HOME/auth.json`，清理旧 OAuth tokens、refresh 时间、agent identity 和 user metadata，避免一个账号配置同时残留 API key 与 OAuth 语义。
- 确认页 diff 与账号配置 snippet 已同步显示最小 auth payload；验证通过 `go test ./internal/wailsapp -run 'TestApplyRelayServiceConfigToLocal|TestGetLocalCodexAuthState'`、相关前端 node tests 与 `npm --prefix frontend run typecheck`。

## Codex auth.json 读取优先级校准

- Codex 源码 `AuthDotJson.resolved_mode()` 先使用显式 `auth_mode`，缺失时才根据 `OPENAI_API_KEY` fallback 到 API Key，否则默认 ChatGPT/OAuth。
- GetTokens `GetLocalCodexAuthState` 已按该优先级修正：`auth_mode=chatgpt` 且残留 `OPENAI_API_KEY` 时仍识别为 ChatGPT/OAuth，可保留 tokens，但给出残留字段 warning；`auth_mode` 缺失且存在 `OPENAI_API_KEY` 才识别为 API Key。
- 回归测试新增 `auth_mode=chatgpt + OPENAI_API_KEY + tokens` 场景，防止后续把 OAuth 登录态误判成 API Key。
