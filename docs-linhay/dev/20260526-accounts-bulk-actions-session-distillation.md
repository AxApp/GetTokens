# 2026-05-26 账号池批量与分组操作会话蒸馏

## 可复用模式

这轮账号池改动确认了一条后续可复用的实现路径：批量选择、分组操作和单卡操作不应该各自发明一套执行逻辑，而应该共享账号动作管线。

1. 选择集合与目标筛选放在 `frontend/src/features/accounts/model/accountSelection.ts`。
2. 删除、刷新、激活、禁用的执行编排放在 `useAccountsActions`。
3. `AccountsToolbar` 和分组标题只发出用户意图，不直接判断后端接口或账号来源差异。
4. 分组选择是批量选择的局部作用域；只有顶部批量选择开启时才显示本组选择 / 取消选择。
5. 分组激活 / 禁用复用批量启停路径，避免出现单卡、批量、分组三套状态更新规则。

## 交互边界

- 批量删除必须保留二次确认。
- 刷新 / 激活 / 禁用允许跳过不支持的账号，并在完成后显示成功、跳过、失败摘要。
- 操作完成后重新对齐列表数据和选中态，不能把已删除账号留在 `selectedAccountIDs`。
- 分组标题右侧常驻轻量操作只放刷新和更多菜单；选择类入口受顶部选择模式控制。
- 危险禁用入口使用红色危险态，不能和普通启用动作同色。
- 选择态工具行使用常规 UI 控件字号，不再使用过小的辅助字号。

## 不纳入

- 不新增后端批量 API；当前阶段复用既有单账号接口。
- 不把批量选择态持久化到本地存储。
- 不把本轮账号页的具体按钮文案升级为 repo-wide 规则。
