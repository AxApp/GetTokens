## 账号页 usage 资源复用

- 背景：继续处理 4000+ 账号下批量刷新和卡片数据同步开销。确认账号页卡片 usage 只是运行时补充态，旧默认会让 Wails/sidecar 重新解析账号池来补 attribution 归属。
- 决策：账号页 `loadAccountUsage()` 默认改为 `resolveAccountKeys=false`，同时请求 `includeUnresolved=true`，前端复用当前 `AccountRecord[]`，先为 sidecar attribution 建一次性索引，再按 `id / quotaKey / authIndex` 本地 join。完整 Usage Desk / 诊断页仍可显式 opt-in 后端账号解析。
- 实现：`frontend/src/features/accounts/hooks/useAccountsUsageState.ts`、`frontend/src/features/accounts/model/accountUsage.ts`。
- 验证：`node --test src/features/accounts/tests/accountUsage.test.mjs`、`node --test src/features/accounts/tests/accountRuntimeSync.test.mjs`、`npm --prefix frontend run typecheck` 通过。
- 沉淀：更新 `.agents/skills/gettokens-performance-governance/SKILL.md`，记录账号卡片 usage refresh 默认复用当前账号快照，避免为卡片展示重复扫描账号池。

## Usage Attribution 安装包观测打点

- 背景：用户准备安装新包到本机，需要在正式运行日志中确认账号页 usage 资源复用是否生效。
- 实现：`internal/wailsapp/usage_attribution.go` 增加 Wails bridge 打点，输出 `usage attribution bridge complete`，包含 `resolve_account_keys`、`include_unresolved`、items/unresolved 数量、`sidecar_ms`、`resolve_ms`、`total_ms`；只有后端解析开启时输出 `usage attribution account resolution complete` 和索引构建耗时。
- 安全边界：日志只输出计数、布尔值和耗时，不输出账号 key 列表、凭证、请求/响应正文。
- 验收：账号页卡片 usage 刷新应看到 `resolve_account_keys=false`；高频 `resolve_account_keys=true` 或 `usage attribution account resolution complete` 表示账号页又误触发后端账号池解析。
- 验证：`go test ./internal/wailsapp -run 'TestGetSidecarUsageAttribution|TestCodexAttributionIdentityStore'` 通过。

## 账号卡片 usage-limit 语义

- 背景：用户在新安装包账号池中看到 `usage_limit_reached` raw JSON 被当成“异常”展示，并出现“重新登录”入口。
- 决策：`usage_limit_reached` 是上游用量已达上限/等待重置的运行态 quota/cooldown 信号，不是安装错误，也不是 OAuth 重新登录可修复的 auth failure。
- 实现：`frontend/src/features/accounts/model/accountPresentation.ts` 识别该 payload，卡片 operational state 显示“用量已达上限”，failure reason 摘要为用户可读的 quota/reset 文案，并让 `isCodexReauthEligible()` 对该状态返回 `false`；`AccountCard` 传入 `t` 以使用中英文 locales。
- 沉淀：更新 `.agents/skills/gettokens-domain-engineering/SKILL.md`，记录 usage-limit 与 reauth/auth failure 的边界。
- 验证：`node --test src/features/accounts/tests/accountPresentation.test.mjs`、`npm --prefix frontend run typecheck` 通过。
