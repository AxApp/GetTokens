# 2026-06-06

- 账号卡片 quota empty badge 的时间差异根因：sidecar `blockReason` 里的 `reset at 2026-...Z` 是 UTC/RFC3339 原始原因；quota row 下方“重置时间”来自 window `resetAtUnix/resetLabel` 并按本地时区格式化。前端展示层不得直接把原始 `quota empty: ...; reset at ...Z` 放入可见 badge，需先归一为本地化短文案，例如 `5H 已空 · 06/06 04:10`，原始 reason 继续保留在数据层供诊断。
- 账号卡片无上限流量统计（`value / ∞`）不应伪造 quota 上限，也不应使用突兀的图表主色进度条。当前采用“活动强度条”：保留 `/ ∞` 文案，宽度按当前累计量相对近期 `trafficBuckets` 基线计算，颜色使用 `text-primary` 低透明混合色，表达近期活跃度而非剩余额度。
- 账号卡片的“刷新额度”是用户理解中的卡片运行状态刷新入口；当卡片存在 Route Guard 规则时，应同时刷新 `GetAllRateLimitStatuses` 并在 Route Guard 区域显示同款扫光反馈。否则 quota 有动画而 Route Guard 不动，会被误解为该区域没有刷新。
- 账号卡片显式刷新时，无上限 usage 活动条也必须显示刷新反馈：顶部刷新、分组刷新、单卡刷新都应触发 usage 刷新 busy 状态并复用同款扫光；后台 usage 轮询保持静默，避免页面周期性自发动画干扰扫读。
