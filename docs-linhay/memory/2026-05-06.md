# 2026-05-06

## 请求编排 OpenAI-Compatible 账号组补齐

- 问题原因：请求编排页虽然调用了 `ListOpenAICompatibleProviders`，但只用 provider 列表生成模型映射，没有把 provider 本体转换成请求账号；因此 `buildRequestAccountGroups` 没有看到 `openai-compatible` 账号，自然不显示兼容 OpenAI 接口的账号组。
- 修复决策：在请求编排模型层新增 OpenAI-Compatible provider 到 `AccountRecord` 的转换，并在真实数据 hook 中合并 `ListAuthFiles`、`ListAccounts` 和 `ListOpenAICompatibleProviders` 三类账号源后再生成请求账号与账号组。
- 验收结果：浏览器预览已看到 `OpenAI-Compatible 组`，选中后显示 `deepseek / deepseek-chat`；截图归档 `docs-linhay/spaces/20260502-request-orchestration-menu/screenshots/20260506/request-orchestration/20260506-request-orchestration-openai-compatible-group-after-v01.png`。

## 请求编排账号参与改为用户勾选

- 设计修正：账号组不应自动把所有兼容账号都视为参与当前流程；兼容性只负责提示“可用”，是否参与由用户在账号列表中勾选。
- 实现决策：`RequestFlow` 新增流程级 `enabledAccountIDs` 白名单，账号列表改为可见 checkbox；取消勾选当前账号时自动切换到同组内仍勾选且可用的下一个账号。
- 验收结果：取消勾选 `codex-prod-01` 后，默认组计数从 `已勾选 2 / 可用 2` 变成 `已勾选 1 / 可用 2`，当前账号自动切到 `codex-lab-02`；截图归档 `docs-linhay/spaces/20260502-request-orchestration-menu/screenshots/20260506/request-orchestration/20260506-request-orchestration-account-checklist-after-v01.png`。
