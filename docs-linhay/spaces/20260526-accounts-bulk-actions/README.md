# Accounts Bulk Actions

## 背景
用户在 `http://localhost:5173/#frame=accounts` 的账号池界面需要先批量选择账号，再一次性执行常见操作：移除、刷新、激活、禁用。当前界面已有选择模式和导出选中，但缺少批量操作闭环，用户需要逐个进入账号卡菜单处理，效率低且容易漏选。

## 目标
- 在账号池选择模式下提供明确的批量操作区。
- 在每个账号分组标题右侧提供低干扰的分组级操作入口。
- 支持对已选账号执行：
  - 批量移除。
  - 批量刷新额度 / 状态数据。
  - 批量激活。
  - 批量禁用。
- 支持对单个分组执行：
  - 选择 / 取消选择本组，且只在顶部批量选择开启后显示。
  - 刷新本组。
  - 激活本组。
  - 禁用本组。
- 操作结果需要更新当前账号列表与选中态，并通过现有消息 / 错误区域反馈失败。
- 保持 `#frame=accounts` 浏览器预览可用，避免依赖桌面窗口才能验证基本交互。

## 范围
- `frontend/src/features/accounts/` 账号池主列表、选择态工具条、账号动作 hook。
- 批量操作相关纯函数与单元测试。
- 中英文文案。
- 必要的无头浏览器截图 / DOM 验收脚本，截图归档到本 space。

## 非目标
- 不新建后端批量 API；第一阶段复用现有单账号删除、启停、刷新接口。
- 不改变账号卡详情弹窗、导入流程、分组 / 排序 / 筛选语义。
- 不调整 Codex / Claude 独立账号列表的渠道路由配置。
- 不引入新的全局选择模型；批量选择只作用于当前账号池过滤结果和已选账号集合。

## 验收标准
1. Given 用户打开 `#frame=accounts`，When 点击“批量选择”，Then 列表进入选择模式，并显示已选数量与批量操作区。
2. Given 过滤结果中有账号，When 用户点击“全选”，Then 当前过滤结果全部进入已选集合；再次点击则只取消当前过滤结果的选择。
3. Given 已选账号数量为 0，When 用户查看批量操作区，Then 移除、刷新、激活、禁用按钮均不可执行。
4. Given 已选账号中存在可刷新额度的账号，When 用户点击“刷新”，Then 仅对支持额度刷新的账号执行刷新，并保留其他已选账号不报错。
5. Given 已选账号中存在可启停的账号，When 用户点击“禁用”，Then 对这些账号设置 `disabled=true`，不可启停账号被跳过并给出结果摘要。
6. Given 已选账号中存在可启停的账号，When 用户点击“激活”，Then 对这些账号设置 `disabled=false`，不可启停账号被跳过并给出结果摘要。
7. Given 用户点击“移除”，When 未确认危险操作，Then 不直接删除账号；When 用户二次确认，Then 对已选账号按现有删除逻辑逐个移除，并清理已删除账号的选择态。
8. Given 任一批量操作部分失败，When 操作完成，Then 成功项保持已生效，失败项在界面错误区域给出摘要，不能静默吞掉。
9. Given 批量操作完成，When 列表重新加载，Then 已不存在的账号不再保留在 `selectedAccountIDs` 中。
10. Given 用户未开启顶部“批量选择”，When 查看任一分组标题，Then 分组右侧只显示刷新和更多菜单，不显示选择按钮。
11. Given 用户开启顶部“批量选择”，When 查看任一分组标题，Then 分组右侧显示选择 / 取消选择入口，并可只影响该分组账号。
12. Given 用户打开分组更多菜单，When 查看菜单项，Then 可以执行激活本组和禁用本组，且复用批量启停结果摘要。
13. Given 用户打开账号卡更多菜单，When 查看危险禁用项，Then “禁用账户”使用红色危险态样式。
14. Given 用户进入批量选择后的选择控制行，When 查看“全选 / 清空选择 / 导出选中 / N 已选”，Then 字号不低于账号页常规 UI 控件字号。
15. 相关前端单元测试、类型检查、构建与浏览器预览验收通过，或明确说明未运行原因与风险。
