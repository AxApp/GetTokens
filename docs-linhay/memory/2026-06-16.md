## 删除账号后 Codex 全局 auth_unavailable 修复

- 用户现场现象：删除另一个账号后，Plus 账号卡片报 `list account store accounts for routeability reconcile: query accounts: disk I/O error (522)`，所有 Codex 会话请求 `http://127.0.0.1:8317/v1/responses` 返回 `503 auth_unavailable: no auth available (providers=codex, model=gpt-5.5)`；重启 App 后恢复。
- 根因：CLIProxyAPI no-watcher account-store 热刷新把 SQLite 读失败误当成“账号库有效为空”，进而把当前进程内所有 account-store runtime auth 清掉；重启后重新读取 SQLite 成功，所以恢复。
- 修复：`SynthesisContext` 记录 `AccountStoreLoadError`；`refreshAccountStoreAuthsWithoutWatcher()` 遇到读库错误时跳过 runtime pruning，保留既有 runtime auth 和模型 registry，只暴露 account-store 错误；有效空库仍按空集合处理。
- 验证：sidecar focused `go test ./sdk/cliproxy -run 'TestServiceRefreshAccountStoreAuthsWithoutWatcherRegistersCodexAPIKeyModels|TestServiceRefreshAccountStoreAuthsWithoutWatcherPreservesRuntimeOnStoreReadError|TestServiceReconcileAccountStoreRouteabilityRepairsMissingRegistryModels|TestServiceReconcileAccountStoreRouteabilityRepairsDegradedRuntimeAuth' -count=1` 通过；`go test ./internal/watcher/synthesizer ./internal/gettokens/accountstore ./internal/api/handlers/management -count=1` 通过；本仓 `./scripts/ensure-sidecar.sh darwin arm64` 已重建本地 sidecar。
- 沉淀审计：该模式已写入 `gettokens-domain-engineering`：account-store hot refresh 必须区分“读失败”和“有效空库”，不得把读失败放大成全局 runtime auth 清空；不升级 `AGENTS.md`。
