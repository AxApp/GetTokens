## Sidecar 账号归因 live 闭环修复

- 本轮 live 调试最终定位到两个真实根因：
  - sidecar fork `shouldPreferUsageAttributionAuthID()` 只匹配了测试里写死的 `api-key`，但 runtime `auth.AccountInfo()` 实际返回的是 `api_key`，导致 live API key / openai-compatible 请求继续错误回落到 `auth-index:*`
  - Wails `GetSidecarUsageAttribution()` 默认没有强制 `include_unresolved=true`，而 raw sidecar summary 在 join 前会先把没有 `accountKey` 的桶放进 `unresolved`；因此前端调用虽然成功，但拿到的是空 `items`
- 已修复 sidecar fork 对 `api_key / apikey` 的兼容，并新增 `TestUsageAttributionEventPrefersAuthIDForAPIUnderscoreKeyType`；同时修复 Wails `GetSidecarUsageAttribution()` 始终向 sidecar 请求 raw unresolved，再在返回前按调用方选项隐藏 unresolved，并新增 `TestGetSidecarUsageAttributionIncludesUnresolvedSourceForJoinEvenWhenCallerDoesNotRequestIt`。
- 还确认了一个构建链风险：`scripts/ensure-sidecar.sh` 只按 `commit + dirty` 判断二进制缓存，无法识别 dirty worktree 内部内容变化。为完成本轮验收，实际执行了 `./scripts/build-sidecar.sh darwin arm64 build/bin` 强制重编 sidecar，再启动 `./scripts/wails-cli.sh dev`。

  - `codex-api-key:26b1c3ff958f` 再次命中 `gpt-5.4`，HTTP 200，raw ledger 新增 `auth-id:codex:apikey:a6ba88c12cad`
